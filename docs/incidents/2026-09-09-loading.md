# Loading and sign-in incident

Reports: blank pages, lazy tools failing until refresh, Ted unable to enter.

Confirmed findings:
- Frequent deployments changed hashed lazy chunks. Previous browser verification
  encountered the reload boundary but did not cover old-tab release transitions.
- Clerk production keys reject vercel.app origins. On the staged production
  deployment the browser logged this error and ClerkProvider rendered null,
  removing even its nested loading fallback. The root error boundary alone was
  insufficient because this was not a React render exception.
- Ted's existing active membership and explicit production identity mapping were
  present. His own browser sign-in has not been reproduced or verified.

Changes:
- Vite build pins emitted JS imports, shared chunks, CSS preload references and
  HTML asset links to the deployment using Vercel's dpl query parameter.
- Project skew max age is 86400 seconds; boundary 1789001491000 excludes releases
  before 2026-09-10 00:51:31 UTC. Keep this boundary when shipping later releases;
  advancing it on every release would break existing sessions again.
- API requests still use current server authorization. No credentials, account
  mappings, role permissions, or membership status were changed.
- HTML boot fallback, independent auth loading watchdog, root error boundary,
  access-check deadline/retry, and stable token getter avoid silent/unbounded startup.
- Known production vercel.app aliases redirect to the canonical custom domain.
  Deployment-protected aliases may still require Vercel login before application
  redirects execute; users should use https://welcometothecampfire.io directly.
- Asset failures can recover once per minute only while online, without input
  edits, and when existing tool-navigation guards allow it. Other failures expose
  retry/reload actions. Saved data is preserved; reload can discard unsaved input.
- Missing /assets files no longer rewrite to index.html.

Validation before final release:
- 151 tests, API syntax check and build passed; dependency audit: zero findings.
- Fixture build verifies entry, lazy, shared and CSS references are pinned.
- Tests cover offline/edit/guard/storage failure, reload-loop suppression and timeout.
- Missing-key browser preview rendered recovery UI.
- Initial staged deployment dpl_CYTYWnZmHBCwy1FxgMgHxWPEQXtd produced pinned HTML;
  its JS/CSS returned 200 with correct MIME through the existing production domain
  before promotion. It was deliberately not promoted after browser QA exposed the
  ClerkProvider null-render behavior; that was fixed in the subsequent revision.
